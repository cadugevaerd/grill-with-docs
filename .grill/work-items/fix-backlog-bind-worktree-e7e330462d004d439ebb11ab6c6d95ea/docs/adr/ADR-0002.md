# ADR-0002 — Provar a resolução por worktree com stub do seam e um caso de git real

- phase: FASE-001

- supersedes: none
- conflicts-with: none

## Contexto

A classe `Resolution` (`tests/validate_backlog_contract.py:95-145`) cobre `BOUND`,
`NEEDS-BIND`, `NEEDS-CREATE` e as duas recusas, sempre sobre um diretório temporário sem
git e com `bound_path == str(self.root)`. Nenhum caso resolve a partir de um caminho
diferente do vinculado, então o bug era invisível à suíte por construção.

`StubToolchain.run` (`40-56`) só sabe casar comandos do backlogctl: a chave é
`argv[2:2+len(prefix)]`, pulando `cli --json`. Um comando `git` passa por ele e recebe
`0, envelope([])`, que não é saída porcelain.

Um stub que devolve a saída porcelain que o autor imagina prova a lógica de conjunto, mas
não prova que a ponte lê o que o `git` real escreve — foi assim que um bug de parsing
sobreviveu a mais de mil testes noutro work item deste repositório.

## Decisão

Dois níveis, ambos em `tests/validate_backlog_contract.py`:

1. **Stub do seam.** `StubToolchain` aprende a responder `argv` de `git` (chave a partir
   de `argv[1:]` quando `argv[0] == "git"`). Casos novos em `Resolution`: `BOUND` quando
   `bound_path` é a worktree de controle e `root` é uma linkada; `NEEDS-CREATE` com nome e
   código derivados da worktree de controle; recusa por ambiguidade; fallback para
   `{root}` quando o `git` falha; `ensure_bind --apply` chamando `backlog bind --path`
   com a worktree de controle. Os casos existentes continuam passando sem edição, porque
   a resposta padrão do stub não é porcelain e cai no fallback.
2. **Um caso com git real.** `git init` + commit + `git worktree add` num diretório
   temporário, resolvendo a partir da worktree linkada com `bound_path` igual ao
   `realpath` da de controle, e exigindo `BOUND`. `git` é dependência declarada e está na
   matriz de CI; o caso não toca a rede.

## Consequências

- A suíte reprova sozinha se a forma do `argv` ou o parsing das linhas `worktree ` mudar.
- Um teste passa a depender de `git` no PATH. É o mesmo pressuposto de
  `validate_gauntlet_*`, não um novo.
- Nenhum teste toca `~/.backlog/backlog.db`: o backlogctl segue stubado.

## Alternativas rejeitadas

- **Só stub**: mais rápido, mas repete a fixture derivada do código. Rejeitada pela
  evidência da memória do projeto.
- **Só git real**: cobre o caminho feliz e deixa ambiguidade e fallback sem caso barato.
