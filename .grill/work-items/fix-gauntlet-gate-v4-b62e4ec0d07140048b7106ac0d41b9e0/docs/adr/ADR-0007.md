## Contexto

`v3_checkpoint_attestation_required` perguntava apenas por v3. Um documento v4 caía no
`return False` e o checkpoint seguia pelo caminho v2 não autenticado — exatamente a
*"quiet downgrade to the unauthenticated v2 checkpoint path"* que o docstring da função
declara impedir. `validate_gauntlet_converge_contract.py:1320` provou: `ship` completava
com verdict `UPDATED` onde deveria vir `ATTESTATION-REQUIRED`.

Generalizar a função para a frontier ativa consertou v4 e abriu o mesmo buraco em v3:
`validate_v3_wiring_contract.py` passou a mostrar checkpoint v3 completando sem atestação.

A assimetria com ADR-0001 é a razão de decidir diferente aqui: recusar um documento antigo
no gate do Gauntlet remove uma **capacidade**; recusá-lo — ou pior, ignorá-lo — neste gate
remove uma **verificação**.

## Decisão

`checkpoint_attestation_required` ativa para qualquer versão de `KNOWN_VERSIONS` e usa o
módulo de gate da versão que o documento declara. v2, ou um documento que não satisfaz
nenhuma frontier conhecida, mantém o ciclo byte-compatível de antes.

O dispatch por marcador vive **somente aqui**. ADR-0001 segue valendo para a ativação do
Gauntlet.

## Consequências

- v3 mantém a atestação que sempre teve; v4 ganha a que faltava.
- Os três testes de `validate_v3_wiring_contract.py` voltam a passar sem serem reescritos,
  o que é o sinal de que a semântica antiga foi preservada, não contornada.
- `except` precisa nomear as duas classes `Failure`. `workflow_v4.Failure` reexporta o
  `Failure` da instância de v3 que **ele** carrega, enquanto `grill_core_module` devolve um
  `workflow_v3` executado separadamente: são classes distintas. Capturar só uma deixava a
  outra escapar como `UNEXPECTED-FAILURE` — foi o que
  `test_v3_checkpoint_late_step_skills_runtime_error_is_one_blocked_json` pegou.
- A função foi renomeada de `v3_checkpoint_attestation_required` para
  `checkpoint_attestation_required`: o nome antigo afirmava um escopo de versão que a
  função deixou de ter.
