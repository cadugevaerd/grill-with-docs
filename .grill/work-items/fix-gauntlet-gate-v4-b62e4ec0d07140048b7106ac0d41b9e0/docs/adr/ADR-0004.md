# ADR-0004 — Separar `EXECUTABLE_VERSIONS` de `KNOWN_VERSIONS` no SSOT

- status: accepted
- evidence-status: verified
- sources: tests/validate_workflow_versions_contract.py:174-183; grill_core/gauntlet.py:415,501,505,513,615-617
- phase: FASE-001
- date: 2026-08-23
- supersedes: none
- conflicts-with: none
- implements: docs/adr/ADR-0003.md

## Contexto

ADR-0003 deprecia v3 como superfície de execução, mas `EXECUTABLE_VERSIONS` colapsa dois
conceitos distintos: quais versões o runtime **executa** e quais ele precisa **saber ler**.
`validate_workflow_versions_contract.py:174-183` amarra cinco tabelas à tupla, então
encolhê-la apagaria a chave `"v3"` de estruturas que a leitura ainda exige.

## Decisão

Duas tuplas no SSOT:

- `EXECUTABLE_VERSIONS = ("v4",)` — versões cujo `WORKFLOW.md` o gate aceita.
- `KNOWN_VERSIONS = ("v3", "v4")` — versões que o runtime sabe ler.

Invariante nova, testada: `set(EXECUTABLE_VERSIONS) <= set(KNOWN_VERSIONS)`.

As **cinco** tabelas por versão passam a ser amarradas a `KNOWN_VERSIONS`:
`SEQUENCE_BY_VERSION`, `TIER_POLICY_BY_VERSION`, `EXECUTOR_STEP_BY_VERSION`,
`REGISTRY_FILENAME_BY_VERSION` e `DEVELOPMENT_SCHEMA_BY_VERSION`.
`EXECUTABLE_VERSIONS` não amarra tabela nenhuma.

## Correção sobre o esboço inicial

O esboço mandava `REGISTRY_FILENAME_BY_VERSION` para `EXECUTABLE_VERSIONS`. A leitura do
código mostrou que isso quebraria: `gauntlet.py:501,505,513,615-617` indexam registry,
catálogo e catálogos confiáveis pela versão que o **activation record** declara, e
`gauntlet.py:415` faz o mesmo com `TIER_POLICY_BY_VERSION`. Activation records são
imutáveis, então um recibo v3 escrito antes deste build seria revalidado depois dele — e
levantaria `KeyError` em vez de veredito. Por isso as tabelas indexadas por versão de
recibo ficam todas em `KNOWN_VERSIONS`.

## Consequências

- `EXECUTABLE_VERSIONS` passa a significar o que o nome diz: a lista que o gate consulta.
- Recibo, sequência, tier e schema v3 continuam legíveis; o dual-read da 4.0.1 sobrevive.
- `validate_workflow_versions_contract.py:174-183` é reescrito para amarrar a
  `KNOWN_VERSIONS`, mais um caso novo para a invariante de subconjunto.
- Nenhum bundle precisa migrar.
