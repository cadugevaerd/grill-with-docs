# ADR-0008 — Este fix é aplicado fora da cadeia atestada, como exceção de bootstrap

- status: accepted
- evidence-status: verified
- sources: WORKFLOW.md (Invocação canônica; Proibição explícita de semantic emulation); gauntlet-init observado em BLOCKED/WORKFLOW-INCOMPATIBLE antes da correção; state.json#development.current_step
- phase: FASE-001
- date: 2026-08-23
- supersedes: none
- conflicts-with: none

## Contexto

O `WORKFLOW.md` exige que toda etapa passe pela cadeia
`skill-resolution → dispatch-intent → skill-invocation → step-output`, sob pena de
`UNATTESTED_STEP_OUTPUT`. Essa cadeia é o Gauntlet, e o Gauntlet estava bloqueado pelo
próprio defeito que este work item corrige: `gauntlet-init` retornava
`WORKFLOW-INCOMPATIBLE` contra o `WORKFLOW.md` deste repositório.

Rodar `specify` e as etapas seguintes teria produzido artefatos sem receipt e morrido em
`partition`, no mesmo gate. Não há ordem de execução em que o atestador conserte a si
mesmo através de si mesmo.

## Decisão

A correção foi aplicada diretamente, fora da cadeia atestada, como exceção de bootstrap
declarada. As etapas de `specify` a `ship` permanecem `pending` no `state.json`: nenhuma
foi executada, e nenhuma é marcada como se tivesse sido.

## Consequências

- Este work item não tem cadeia de receipts, e isso está registrado aqui em vez de ficar
  implícito num `state.json` que não menciona o assunto.
- A evidência que substitui o receipt é a suíte: 1238 testes em 26 validadores, exit 0,
  incluindo a suíte de ativação que agora materializa a frontier de `ACTIVE_VERSION` e
  exige `gauntlet-init` bem-sucedido — a prova direta de que o sintoma relatado morreu.
- **Isto não é precedente.** A exceção se justifica por uma condição verificável e
  estreita: o Gauntlet estava indisponível *por causa* do defeito sob correção. Qualquer
  trabalho posterior encontra o Gauntlet funcionando e não tem essa desculpa.
- O ciclo de 11 etapas fica disponível para os próximos work items a partir desta versão.
