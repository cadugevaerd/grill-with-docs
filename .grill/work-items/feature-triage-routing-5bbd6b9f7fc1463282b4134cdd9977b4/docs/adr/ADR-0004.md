# ADR-0004 — A triagem nasce consultiva; exigi-la é trabalho subsequente

## Contexto
Tornar a triagem pré-requisito de `init` e `hotfix` muda a superfície pública de dois comandos que todo consumidor do plugin já usa, e obriga a decidir ao mesmo tempo o formato do bloco selado dentro do `WORK-ITEM.json`, a propagação do id para o backlog e o comportamento de bundles criados antes da triagem existir. Entregar isso junto com o mecanismo faria uma mudança quebrar duas coisas ao mesmo tempo, sem que nenhuma tivesse sido exercitada em uso real.

## Decisão
A 3.3.0 entrega a triagem como capacidade verificável e **não** a exige. `init` e `hotfix` ficam byte-intactos. A obrigatoriedade — `TRIAGE-REQUIRED`, `ROUTE-MISMATCH`, bloco selado no bundle — é o trabalho seguinte, com work item próprio.

## Opções e custos
- **Consultiva primeiro:** risco zero para consumidores existentes, e o mecanismo é exercitado antes de virar pré-requisito; **custo:** durante uma versão o defeito de fundo continua de pé, porque `feature` e `fix` seguem produzindo o mesmo bundle.
- **Obrigatória de imediato:** resolve o defeito de fundo numa só entrega; **custo:** quebra `init` para todo consumidor na mesma versão em que o formato do registro estreia, sem uso real que confirme que o formato aguenta.

## Consequências
Esta milestone não resolve o problema que a motivou; ela constrói e prova o mecanismo que vai resolvê-lo. Isso está declarado no CHANGELOG e no CLAUDE.md para que a versão não seja lida como entrega completa da separação de trilhas. O `ROADMAP.md` deste work item registra explicitamente que as fases seguintes não entram aqui como fases abertas: uma milestone não se declara terminal carregando trabalho que não entregou.
