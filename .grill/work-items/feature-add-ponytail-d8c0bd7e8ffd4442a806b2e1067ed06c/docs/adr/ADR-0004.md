# ADR-0004 — Instalação do ponytail delegada à CLI do harness sob `--allow-install`, escopo `user`, com confiança no marketplace declarada no manifesto

## Contexto
O core nunca baixa bytes; cada instalação é delegada a quem é dono do artefato. Para plugin de harness o dono é a CLI do runtime: `claude plugin marketplace add DietrichGebert/ponytail` + `claude plugin install ponytail@ponytail` (escopo `user` por padrão) e `codex plugin marketplace add DietrichGebert/ponytail` + `codex plugin add ponytail@ponytail`. Ambos rodam sem prompt. O marketplace é de terceiro; o precedente do catálogo `community` do Spec Kit registra essa confiança no manifesto, revisável no diff. A instalação existente na máquina de referência é `scope: user`.

## Decisão
Sob `--allow-install`, o preflight executa, pelo runtime ativo, os dois passos do dono (`marketplace add` seguido de `install`/`add`), no escopo `user`. A sequência fica declarada em `dependencies.json` (`install` por runtime), e a confiança no marketplace `DietrichGebert/ponytail` é essa declaração. Sem a flag, o preflight só nomeia a remediação; quem conduz a sessão pergunta ao humano antes de reexecutar com `--allow-install`.

## Opções e custos
- **A (escolhida): delegar, escopo `user`.** benefício: simetria Claude/Codex, nada versionado no consumidor, mesmo modelo do Spec Kit; **custo:** confiar num marketplace de terceiro — mitigado por estar explícito no manifesto.
- **B: delegar com `--scope project` no Claude.** benefício: plugin registrado no repositório consumidor; **custo:** Codex não tem equivalente conhecido, criando assimetria; escreve em `.claude/settings.json` de terceiro (política que ADR-0001 evita).
- **C: só remediação.** benefício: zero confiança automática; **custo:** trata o ponytail pior que o Spec Kit e o backlog, contradizendo "stack oficial".

## Consequências
- `dependencies.json` ganha `install` por runtime para o ponytail; `remediation()` já resolve placeholders e listas de comandos.
- Testes com `Toolchain` fake provam que a sequência é a declarada e que nada roda sem `--allow-install`.
- O "pedir para instalar" é responsabilidade da skill condutora (SKILL.md), não do core.
