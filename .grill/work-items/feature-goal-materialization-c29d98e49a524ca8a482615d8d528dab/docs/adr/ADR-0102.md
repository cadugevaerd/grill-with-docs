# ADR-0102 — Documento humano incompatível é preservado e reportado

## Contexto

`goal.md` é materializado na **raiz** do projeto consumidor, onde um arquivo com
esse nome pode ter sido escrito por uma pessoa, para outra finalidade.

O `WORKFLOW.md` já resolve o caso equivalente: workflow humano preexistente
permanece byte-intacto e é reportado como incompatível, nunca sobrescrito.

## Decisão

A materialização é no-clobber. Documento existente que não case o contrato
permanece byte a byte como está e é reportado como incompatível. O `init` nunca
substitui, nunca renomeia e nunca faz backup silencioso.

O estado reportado segue o vocabulário já usado para o workflow: `CREATED`
quando o arquivo nasce, `REUSED` quando já existe e casa o contrato,
`PRESERVED` quando existe e não casa.

## Opções e custos

- **A: preservar e reportar.** **Custo:** o consumidor com arquivo homônimo
  nunca recebe o documento gerenciado até agir; o `init` não resolve por ele.
- **B: sobrescrever com backup.** Benefício: o documento chega sempre.
  **Custo:** destrói trabalho humano com base numa colisão de nome, e o backup
  é consolo, não consentimento.
- **C: materializar sob outro nome quando houver colisão.** Benefício: nada se
  perde. **Custo:** dois nomes possíveis para o mesmo contrato, e o goal loop
  passa a ter de descobrir qual ler.

## Consequências

- O relatório do `init` precisa distinguir os três estados sem ambiguidade, para
  que `PRESERVED` não pareça sucesso.
- Um consumidor pode ficar sem o documento indefinidamente. É o preço de não
  destruir arquivo alheio, e está declarado.
