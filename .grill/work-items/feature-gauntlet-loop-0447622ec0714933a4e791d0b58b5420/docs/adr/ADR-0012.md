# ADR-0012 — Cap de workers é concorrente, não cumulativo

O limite de 1 a 5 workers configurado na ativação (FASE-001) governa **concorrência**: quantos workers podem estar simultaneamente não-terminais em uma run, não quantos workers a run pode criar ao longo de toda a sua vida. O Store shipado pela FASE-002 conta o tamanho total do mapa `workers`, o que travaria qualquer run em cinco workers para sempre — inviável para um Execution DAG com mais de cinco nós, incluindo o da própria FASE-002.

A FASE-003 estende a validação do Store para contar apenas workers cujo estado não é terminal; um worker terminal libera seu slot de concorrência mas seu registro permanece no journal para auditoria (poda/arquivamento do mapa vivo é detalhe de implementação da FASE-003, não desta decisão). Um worker de substituição por stall e um retry de falha transitória contam contra o mesmo cap concorrente.
