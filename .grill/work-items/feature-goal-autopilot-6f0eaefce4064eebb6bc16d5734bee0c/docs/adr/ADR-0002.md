# ADR-0002 — goal.md cobre as duas trilhas, separadas por PLAN_ONLY_STOP

## Contexto

O `WORKFLOW.md` v4 deste repositório declara duas trilhas separadas por uma
fronteira dura:

- **Pré-ciclo GWD** — `init`, `preflight`, `triage`, gate constitucional,
  entrevista incremental, `audit`. Termina em `PLAN_ONLY_STOP`, que ocorre
  **antes de `specify`**: "a skill prepara e audita entradas, entrega o path do
  handoff selecionado e para".
- **Ciclo externo de 11 etapas** — `specify → plan → checklist → tasks →
  analyze → partition → implement-parallel → converge → verify → review →
  ship`, que "pertence ao executor posterior, nunca à sessão grill-with-docs".

## Decisão

`goal.md` cobre as duas trilhas num só documento, com `PLAN_ONLY_STOP` como
fronteira nomeada e explícita entre elas. Cada trilha tem seu próprio critério
de conclusão e seu próprio conjunto de pontos de interação.

## Consequências

- O documento precisa dizer, sem ambiguidade, em qual trilha o loop está e o
  que conclui cada uma — um goal que confunde as trilhas atravessaria
  `PLAN_ONLY_STOP` sem perceber, que é exatamente a violação que a cláusula
  "Feature/fix plan-only" proíbe.
- Atravessar de uma trilha para a outra **não** é automático: é um ponto de
  interação (ver DQ-0004).
- O documento fica maior e carrega dois contratos de parada em vez de um.

## Alternativas rejeitadas

- **Só o ciclo v4**: maior autonomia por turno, mas deixa à mão justamente
  `init` e entrevista, que é onde o trabalho nasce.
- **Só o pré-ciclo**: automatiza a parte mais interativa do protocolo; ganho
  por turno baixo.
