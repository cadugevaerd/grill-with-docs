# ADR-0001 — O registro de extensões é a fonte de verdade, não a saída do CLI

## Contexto
`installed_extensions` (`ensure_dependencies.py:160`) tokeniza a saída **crua** de `specify extension list`:

```python
return set(re.findall(r"[A-Za-z0-9][A-Za-z0-9._-]*", output))
```

A linha do slug é `\x1b[2mgit\x1b[0m`. O regex ancora em `[A-Za-z0-9]`, casa a partir do `2` do `[2m` e produz `2mgit` — nunca `git`. Medido no repositório com as quatro extensões instaladas e `Status: Enabled`:

| slug | slug puro no set? | token `2m<slug>`? |
|---|---|---|
| `git` | não | sim |
| `agent-assign` | não | sim |
| `bugfix` | **sim** | sim |
| `verify-review-ship` | não | sim |

São **duas** falhas, não uma. A primeira é o ANSI. A segunda é o escopo do `findall`: ele varre a saída inteira, então `bugfix` casa pela palavra solta na linha de descrição da própria extensão (`Structured bugfix workflow — capture bugs...`), não pelo slug. O parser acerta zero das quatro pelo caminho correto; o único "present" é falso positivo. Remover o ANSI sozinho deixaria a segunda falha viva.

O efeito prático não é só ruído: `preflight` devolve `MISSING-DEPENDENCY` com o ambiente íntegro, e o relato empurra o operador a rodar `--allow-install` supondo que falte confiança de catálogo — quando o catálogo community já está registrado com `install_allowed: true` e é reportado como `present`. Um defeito de detecção que induz ampliação desnecessária de superfície de confiança.

Alternativas de fonte foram medidas antes de decidir: `specify extension list` **não tem modo machine-readable** (só `--available` e `--all`); `NO_COLOR=1` não limpa os escapes (sobra `\x1b[1m`/`\x1b[2m`); `TERM=dumb` limpa, mas amarra a correção a comportamento de env de uma versão do Rich/Typer.

## Decisão
A detecção passa a ler `.specify/extensions/.registry` — JSON com `schema_version`, slug exato como chave, `enabled` e `version` — e deixa de parsear a saída do CLI. Sem fallback para o parser de CLI.

## Opções e custos
- **Ler `.registry` (escolhida):** mata as duas classes de falha de uma vez, porque não há tokenização nem texto livre onde um substring possa casar; dispensa subprocess, roda offline e é testável no CI sem `specify` real; e preenche `version`, que hoje volta `null`. **Custo:** `.registry` é arquivo interno do spec-kit (dot-prefixed) e seu contrato é privado — tem `schema_version`, mas pode mudar sem aviso.
- **Strip de ANSI + casar só a linha do slug:** permanece no contrato público do CLI. **Custo:** continua preso ao layout visual do Rich/Typer, que muda entre versões; não dá `version`; e exige manter o seam `Toolchain` só para este caminho.
- **`.registry` com fallback para o CLI:** nenhum ponto único de falha. **Custo:** dois caminhos para manter, testar e auditar — e o caminho de fallback é exatamente o frágil, então o custo de manutenção é pago para preservar a fonte menos confiável.

## Consequências
A verificação deixa de depender de como o spec-kit **desenha** a saída e passa a depender de como ele **registra** o estado, que é o dado real. O seam de teste muda de `Toolchain.run` para leitura de arquivo, o que torna o teste um fixture JSON em vez de mock de subprocess — mais simples e sem `specify` no CI.

Em troca, o grill passa a depender de um contrato privado do spec-kit. Isso precisa ser tratado explicitamente: uma mudança de `schema_version` não pode ser lida como "nenhuma extensão instalada", sob pena de trocar um falso negativo por outro. Como tratar ausência e schema desconhecido é decisão própria, aberta em DQ-0002.
