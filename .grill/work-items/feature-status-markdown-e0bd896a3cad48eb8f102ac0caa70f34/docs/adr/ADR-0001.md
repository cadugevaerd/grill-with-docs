# ADR-0001 — JSON permanece padrão e Markdown vira projeção humana canônica

## Contexto

O core já retorna `grill-status/v1` em uma única linha JSON, com ordenação e testes de repetição byte-idêntica. Automações e validadores dependem dessa superfície. A variação relatada ocorre depois da coleta: a skill recebe dados estruturados, mas não tem renderer humano obrigatório e pode formular uma resposta diferente a cada invocação.

## Decisão

`status` mantém JSON como formato default e ganha `--format json|markdown`. O Markdown é renderizado pelo core, e a skill deve invocar esse formato e reproduzir o stdout literalmente, sem interpretação própria.

## Opções e custos

- **Projeção dual (escolhida):** preserva automações e fixa a experiência humana; **custo:** mantém dois formatos públicos e exige cobertura de compatibilidade.
- **CLI vira Markdown:** simplifica a invocação humana; **custo:** quebra consumidores JSON e o contrato público existente.
- **Agente formata o JSON:** não altera a CLI; **custo:** preserva exatamente a fonte da variação que motivou o trabalho.

## Consequências

O JSON recebe somente campos aditivos para classificação. O renderer Markdown passa a ser a única autoridade de apresentação humana. Exit codes e seleção por `--work-id`/`--current-worktree` permanecem comuns aos dois formatos.
