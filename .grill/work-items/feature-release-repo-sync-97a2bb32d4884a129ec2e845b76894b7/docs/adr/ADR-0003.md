# ADR-0003 — A cópia vendorizada é o espelho de plugin/ mais o README, sem testes

## Contexto

O shape publicado hoje não é o shape canônico. A cópia em `claude-skills/plugins/grill-with-docs/` contém `.claude-plugin/`, `hooks/`, `skills/`, `README.md` e `tests/`, mas não `.codex-plugin/`. O canônico `plugin/` contém `.claude-plugin/`, `.codex-plugin/`, `hooks/` e `skills/`, sem `tests/` e sem `README.md`.

Há contradição direta com o contrato do próprio repositório: `tests/validate_distribution.py:27` afirma `assert not list(PLUGIN.rglob("tests"))`, ou seja, o bundle publicável não contém testes. Ainda assim a cópia publicada os carrega — e desatualizados: são cinco validadores, faltando `validate_distribution.py` e os dois acrescentados em 2.5.0.

## Decisão

A publicação copia `plugin/` na íntegra, mais o `README.md` da raiz do repositório, para `plugins/grill-with-docs/` nos dois marketplaces. Testes ficam fora. Os dois marketplaces recebem conteúdo idêntico, incluindo ambos os manifests.

## Opções e custos

- **Espelho de `plugin/` + README (escolhida):** honra o contrato já validado no CI e mantém uma única rotina de cópia; **custo:** a primeira publicação remove `tests/` da cópia do `claude-skills`, gerando diff grande, e o consumidor perde a opção de rodar validadores a partir do plugin instalado; reversão baixa.
- **`plugin/` + README + `tests/`:** preserva o shape atual e permite ao consumidor verificar o bundle instalado; **custo:** exige afrouxar `validate_distribution.py:27`, que existe justamente para manter o bundle enxuto, e leva fixtures junto; reversão baixa.
- **Espelho por agente:** cada marketplace carrega só o manifest que consome; **custo:** duas rotinas de cópia e um modo de falha pior — manifest ausente é mais difícil de diagnosticar do que manifest extra e inerte; reversão baixa.

## Consequências

Positivas: o bundle publicado passa a ser byte a byte o que o CI valida; uma rotina de cópia serve os dois marketplaces; some a divergência silenciosa entre o que se testa e o que se distribui.

Negativas: quem hoje roda os validadores a partir de `plugins/grill-with-docs/tests/` perde esse caminho e precisa clonar o canônico. Como os testes publicados já estão duas versões atrás e incompletos, o caminho existente não era confiável.

Dependências: o `README.md` da raiz descreve instalação pelos dois agentes; ao ser publicado dentro do marketplace ele permanece correto, porque documenta o repositório canônico como fonte.
