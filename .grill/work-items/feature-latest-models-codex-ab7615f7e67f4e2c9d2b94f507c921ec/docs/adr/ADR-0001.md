## Contexto

O binding tier→modelo do runtime Codex é um id literal de uma geração (`gpt-5.6-luna/terra/sol`), e `tier_models.resolve_model` o devolve sem consultar o catálogo; 7 workers reais rodaram `gpt-5.6-terra` com `gpt-6-*` já listados. O autor/revisor Codex da policy de orquestração tem o mesmo padrão (`gpt-6-astra` literal). O Claude não sofre isso: os tiers usam aliases (`haiku/sonnet/opus`, `fable`) que o harness resolve para o mais recente.

O Codex não oferece alias equivalente: o catálogo (`codex debug models`) só tem slugs explícitos, sem campo de família ou alias, e um nome curto como `sol` é aceito sem erro com "fallback model metadata" e repassado literal à API. O alias de API `gpt-6` citado na documentação embutida roteia para Astra, não é verificável localmente e não expressa tier.

## Decisão

1. No runtime Codex, cada tier do binding e cada papel Codex da policy de orquestração declara uma **família** (`luna`, `terra`, `sol`, `astra`), não um slug.
2. No despacho, o core resolve a família para o slug **listado** de menor `priority` daquela família no catálogo local do Codex (`models_cache.json` sob o home do Codex), por leitura de arquivo local, sem subprocesso e sem rede.
3. O slug resolvido é gravado de forma durável (worker record; observação do especialista), para que "qual modelo rodou" continue fato, não memória de sessão.
4. Catálogo ausente, ilegível, ou família sem slug listado: recusa nomeada fail-closed `TIER-MODEL-UNRESOLVED` (com runtime, tier/papel, família e caminho do catálogo) antes de qualquer worktree, lease ou payload. Sem fallback para slug antigo.
5. Tier `medium` mantém a família `terra` (hoje `gpt-5.6-terra`); sobe sozinho quando uma terra mais nova for listada com menor `priority`; caso contrário, mantém a terra preferida.
6. Runtime Claude, aliases de tier Claude e a recomendação textual do líder (`Sol`/`Opus`) permanecem como estão; o par autor/revisor Claude da policy de orquestração muda de `fable` para o alias `opus` pelo ADR-0002.

## Alternativas rejeitadas

- Pegar o topo do catálogo sem família: ignora tier e quebra o piso não-frontier da decisão de projeto `docs/adr/0013-worker-model-floor.md`.
- Usar o alias de API `gpt-6`: não verificável localmente, cai em fallback metadata, sem tiers, aponta para modelo frontier.
- Manter pin literal atualizado para `gpt-6-*` com checagem de defasagem: o bug volta a cada geração.
- Fallback silencioso para slug `last-known`: reproduz exatamente o defeito atual.
- `medium` migrar para `luna` ou lista de famílias por tier: perde a distinção small/medium ou exige critério novo entre famílias.

## Consequências

- O formato de `models_cache.json` do Codex passa a ser dependência declarada; mudança de formato degrada para recusa nomeada, nunca para modelo errado.
- Sem Codex com catálogo local, nenhum worker/especialista Codex é despachado; CI continua offline pelos seams injetáveis.
- O frontier flag passa a ser declarado por família; o piso não-frontier da decisão de projeto `docs/adr/0013-worker-model-floor.md` continua valendo sobre o slug resolvido.
- A policy de orquestração v1 é selada por `policy_sha256` em contextos existentes; a mudança não pode reescrever em silêncio o que contextos selados verificam (ver PLAN-CONTEXT).
