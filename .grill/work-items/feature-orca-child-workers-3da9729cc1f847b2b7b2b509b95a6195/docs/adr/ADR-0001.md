# ADR-0001 — Sessão líder coordena a Run Orca e todo especialista ou worker é child

## Contexto
- O guia Orca 1.4.200 dá ao **coordenador** os comandos `run-create`, `worker-start` e `check --wait`, executados do próprio terminal. Cada child recebe um preâmbulo com Task e Dispatch, encerra com `worker_done` e é liberado com `worker-release`. Children aninhados obedecem `nested_worker_depth_exceeded`, e uma Run nova não zera a profundidade. (verified)
- A candidata 6.0.0 exige que o próprio líder seja um Dispatch: `agent_runtime.py:754-755` recusa qualquer `session_ref` fora de `orca:ctx-*`, e `grill_workspace.py:1510-1514` exige `ORCA_TERMINAL_HANDLE`. Nenhum código cria child; o core só lê `worker-show` (`agent_runtime.py:757`). (verified)
- Em `grill-implement-parallel/SKILL.md:45-53`, os workers saem como subagente nativo (`plugin/agents/gauntlet-worker-medium.md`, `model: sonnet`), mecanismo que só existe no Claude Code. (verified)
- Resultado: nenhuma instrução diz ao agente como invocar um child, e o comportamento muda conforme a CLI.

## Decisão
A sessão líder, que é a sessão do humano, é o **coordenador** Orca: cria a Run e inicia cada child pelo próprio terminal. Autores e revisores de especialista, além dos workers de `implement-parallel`, são **children** criados por `orchestration worker-start`. O mesmo procedimento vale no Claude Code e no Codex. O core deixa de exigir líder `orca:ctx-*` e passa a observar cada child pelo seu Dispatch. O líder continua sendo a única Evidence Boundary.

## Opções e custos
- **A (escolhida) — líder coordena, todos child:** um só nível de aninhamento, humano conversa direto com o líder, procedimento idêntico entre CLIs; **custo:** mudar `init`/`gauntlet-orchestration-adopt` e o adapter de líder da 6.0.0; reversão exige restaurar a exigência `orca:ctx-*`.
- **B — líder também é child:** mantém o core 6.0.0 como está; **custo:** dois níveis de aninhamento consomem o limite de profundidade, e o humano deixa de falar direto com o líder.
- **C — só workers viram child:** diff menor; **custo:** a independência de autor/revisor continua dependendo do mecanismo nativo de cada CLI, que é exatamente o que o pedido quer eliminar.

## Consequências
- Positivas: um único procedimento de invocação, proveniência Orca para todo julgamento independente e fim do agente `gauntlet-worker-medium` como mecanismo de despacho.
- Negativas: depende do ship da candidata 6.0.0 e reabre o contrato de adapter de líder dela.
- Dependências: DQ-0004 (Orca indisponível), DQ-0005 (binding modelo/esforço), DQ-0007 (dono do worktree).
